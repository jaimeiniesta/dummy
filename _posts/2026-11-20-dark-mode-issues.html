This site has a light theme, a dark theme and a "system" option that follows prefers-color-scheme. System is the default, so a browser that emulates prefers-color-scheme: dark gets the dark theme. Every case below behaves differently depending on the colour scheme. Scan this page with prefers-color-scheme: light and with prefers-color-scheme: dark and compare the results.

You prefer a dark color scheme.

Canary. The box above only exists in the dark theme and its text has low contrast on purpose. If the scan reports color-contrast on #dark-mode-canary, the preference reached the browser.
Light: no issue.
Dark: color-contrast on #dark-mode-canary.

1. Hard-coded background, themed text

This notice has a hard-coded light yellow background, but its text colour comes from the theme. In the dark theme it becomes light text on a light background.

Light: no issues.
Dark: color-contrast on the notice.

2. Hard-coded text, themed background

This box was designed in dark mode: its text colour is a hard-coded light grey, while the background follows the theme.

Light: color-contrast on the box.
Dark: no issues.

3. Content that only exists in the dark theme

Night owls get a special mascot and a link to their profile:

Light: no issues — the block is display: none.
Dark: image-alt on the chicken, link-name and image-alt on the icon link.

4. Content that only exists in the light theme

Early birds get a sunny goldfish:

Light: image-alt on the goldfish.
Dark: no issues — the block is display: none.

5. Form controls without color-scheme

The site never declares color-scheme, so the browser keeps drawing native form controls with a light background. This field inherits the page text colour.


Light: no issues.
Dark: light text on a white field. Axe reports color-contrast on the input.

6. Theme colours not adjusted for the dark background (site-wide)

These styles come from the site stylesheet, so they affect every page. Inline code like prefers-color-scheme keeps its hard-coded light background, and so do highlighted code blocks:

{% highlight css %} @media (prefers-color-scheme: dark) { body { background: #1b1b1b; } } {% endhighlight %}

Links like the FAQ keep the blue designed for a white background, and the post date and footer use a grey that is too dark.

Light: link, post date and footer contrast issues that minima already had.
Dark: additional color-contrast issues on inline code and code blocks, and lower contrast on links, the post date and the footer.

7. The theme switcher (site-wide)

The light / dark / system switcher in the header is on every page. Its buttons only contain an icon, so they have no accessible name, the group has no label, and the selected option is only shown with colour.

Light and dark: button-name on the three buttons.
